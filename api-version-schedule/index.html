At each cut

JSON-RPC and the Game add-on API cross a major this cycle, so both are banded: every pre-release cut carries the outgoing major, and the new one appears at 22.0.

The band is the number at the cut. A change landing inside a window increments the minor from there — 13.201, 13.202 — and the next cut jumps to the next band, discarding whatever is left. The gaps are headroom, not a count.

Python, the skin API and the remaining binary add-on APIs are not banded. They cross no major this cycle, keep the numbers in §01, and stop moving at RC1.

Rules

  • One major per surface per release. It appears at 22.0 and nowhere earlier.
  • Breaking changes close at Beta 1, additive changes at RC1. Fixes stay open for the life of the branch.
  • Floors do not move after Beta 1 — _MIN in versions.h, backwards-compatibility abi in an addon.xml. Build against Beta 2 or later and the binary loads on 22.0.
  • A version never goes backwards and never reaches the next cut’s band ahead of that cut.

Enforcement

Every number above is declared in api-versions.json, beside version.txt. CI validates each pull request against it.

{
  "release": { "major": 22, "codename": "Piers" },
  "surfaces": [
    {
      "id":      "jsonrpc",
      "path":    "xbmc/interfaces/json-rpc/schema/version.txt",
      "read":    "key:JSONRPC_VERSION",
      "banded":  true,
      "cut":     "13.200",
      "release": "14.0"
    },
    {
      "id":      "addon.game",
      "path":    "xbmc/addons/kodi-dev-kit/include/kodi/versions.h",
      "read":    "define:ADDON_INSTANCE_VERSION_GAME",
      "banded":  true,
      "cut":     "6.200",
      "release": "7.0",
      "floor":   "6.0.0"
    },
    {
      "id":      "python",
      "path":    "addons/xbmc.python/addon.xml",
      "read":    "xml:/addon/@version",
      "banded":  false,
      "release": "3.1",
      "floor":   "3.0.0"
    }
  ]
}

The phase comes from VERSION_TAG. A pull request fails if a version falls below its band, reaches the next band before its cut, moves a floor, moves an unbanded surface after RC1, or goes backwards. cut is re-baselined on the cut commit and nowhere else.
