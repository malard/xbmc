Plainly

Ask Kodi what language a soundtrack is in and it answers eng or en for the same film in the same response, depending where the track came from. This picks one answer for everything outside Kodi.

Substance

  • CLanguageTag replaces bare strings through the demuxers, SelectionStream, StreamInfo and the player.
  • Three exits, three notations: BCP 47 on the wire, 639-2/B in the database, whatever the disc library takes.
  • Ten latent defects fixed en route, two of them build-dependent data corruption.

01Shape of the change

Player.GetProperties served ISO 639-2/B for embedded streams and the filename-derived tag for external subtitles — eng and en in one response.

A bare string never states its notation, so every receiver guessed. Preferences compared against streams in another notation never matched, failed conversions left the caller's output untouched to be read as stale, and normalisation happened on some paths and not others.

A language is now parsed into a tag at the edge where it enters, travels as a tag, and is narrowed only where it leaves.

The carrier is CLanguageTag (xbmc/utils/LanguageTag.h): one canonical BCP 47 string.

Four structs carry it and flip together: CDemuxStream, SelectionStream, StreamInfo, ExternalStreamInfo. Closed captions become the explicit undetermined tag rather than an invented code.

02Matches

bool CLanguageTag::Matches(const CLanguageTag& other) const
{
  // Two tags that are already the same name the same language, without any conversion
  if (StringUtils::EqualsNoCase(m_tag, other.m_tag))
    return true;

  // Narrowing drops the subtags, leaving the language each tag names
  return CLangCodeExpander::CompareISO639Codes(AsIso6392B(), other.AsIso6392B());
}
  • A preference test. en, eng, en-AU and en-GB all match.
  • Not RFC 4647 matching. Symmetric: nothing is more specific, nothing partly matches. Ranking varieties needs the subtags.
  • An extlang qualifies its prefix. zh-yue matches zh, not yue. Both asserted in TestLanguageTag.
At the merge base

CompareISO639Codes compared expanded English names, so en-AU matched neither eng nor en-GB. zh-yue did not match yue then either.

03Three boundaries

The tag is the internal carrier. Every exit states its notation, and the three answers differ for reasons that are not aesthetic.

ExitNotationWhy
Public API
JSON-RPC, Python		 BCP 47 The only notation that expresses what media declares, and already what the external subtitle path produced.
Persistence
streamdetails		 ISO 639-2/B Unchanged. Smart playlist rules are user-authored SQL fragments in .xsp files, not rows. A stored notation change stops them matching, and no migration reaches a file Kodi does not own.
Disc libraries Theirs libdvdnav takes ISO 639-1, libbluray 639-2/T. Getters serve a tag and each consumer narrows, replacing a double conversion through 639-1 that lost languages libbluray would have accepted.

The persistence constraint is recorded above the CStreamDetail classes in StreamDetails.h. Library values therefore carry a language only, never a region; Serialize() widens the persisted form on the way out, and the schema states this per field.

The skin surface keeps its spelling. Eight sites that hand-rolled the same lookup-and-fall-back-to-Unknown now share CGUIInfoUtils::FormatLanguage.

The decision to take explicitly

A 3.0-ABI add-on does not opt in: it starts receiving en where it received eng. Serving 639-2 to 3.0.0 callers and BCP 47 to 3.1.0 callers was rejected — it makes language semantics depend on the caller, and would be carried indefinitely.

06Reviewing it

Ordered so 66 files need not be read as one diff: isolated fixes, expander cleanup, the type with no callers, adoption, then the wire formats one surface per commit.

The split that matters

The adoption commit changes no wire format — every output narrows back to ISO 639-2/B at the end of it. The large mechanical commit is reviewable for type correctness alone; the commits after it contain nothing but contract.

Tests

  • TestLanguageTag (new) — narrowing losses, verbatim retention, Matches across notation, region, script, extlang, undetermined and zxx, the withdrawn spellings, FindInText parameterised.
  • TestLangCodeExpander — the 639-2/T fallback, special-scope codes returning empty, bol failing.
  • TestStreamDetails — the serialization boundary: eng→en, chi→zh, unrecognised pass-through.
  • TestBcp47, TestLangInfo, TestUtil — extension length, deprecated subtag replacement, policy setting values, subtitle filename tokens.

07Non-goals

  • Extlang canonicalisation. Bcp47.cpp carries a @todo for the rest of RFC 5646 step 3, so zh-yue and yue remain different tags — as they were before this change.
  • DVD is bounded by ISO 639-1. libdvdnav takes two letters, so a language without an alpha-2 code cannot be expressed to it and the navigator's existing fallback to en applies. The same rework is what lets libbluray receive such a language correctly.
  • Library values carry no region. A consequence of the persistence decision in §03.
  • The skin surface is unchanged. Its own compatibility surface, and no reason to move it alongside the wire format.
